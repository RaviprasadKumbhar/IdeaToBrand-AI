## 1. Problem: The "One-Prompt Trap"

Founders often start with a single rough premise: *"I want to build an app that helps students find teammates."*

When founders turn to generic AI tools for branding, they fall into the **One-Prompt Trap**:
$$\text{Single prompt} \longrightarrow \text{Monolithic generation} \longrightarrow \text{Hollow, generic text dump}$$

Such tools produce cliché names, flatter the founder without testing viability, confuse facts with unverified assumptions, and fail to ensure that the tagline, visual language, voice, and launch strategy cohere as an integrated brand system.

---

## 2. Solution: Staged AI with Adversarial Critique

**FOIL** breaks branding into a deliberate, multi-stage reasoning pipeline where every stage has a distinct strategic responsibility.

### Key Innovations:
1. **Strategist + Critic Dual-Agent Architecture**: Every proposal generated by the Strategist AI is immediately reviewed by an adversarial Critic AI. The Critic scans for clichés, audience mismatch, contradictions, vagueness, and bias—and **mandates sharper alternatives** with evidence before a founder can approve.
2. **Explicit Choke-Point Approvals**: AI drafts cannot approve themselves or mutate project state. All approved decisions flow strictly through the `writeApprovedDecision` choke point, creating an auditable revision log.
3. **Non-Destructive Scenario Probe**: Founders can explore "What-If" hypotheses (e.g. pivoting target audience) in isolated branch memory without destroying or overwriting their approved brand system.
4. **Holistic Consistency Audit**: Runs across the entire approved identity before release, checking cross-field coherence across naming, visual identity, tone, and launch messaging.
5. **Gated Export**: Exporting the brand system fails automatically if any stage is unapproved or any required consistency finding remains unresolved.

## 3. The 7-Stage Brand Pipeline

```
[ Idea Input ]
      │
      ▼
1. Discovery ──────► Core problem, audience, context, user goals, facts vs assumptions
      │
      ▼
2. Positioning ────► 2 Divergent directions (A/B) with value propositions & strategic rationales
      │
      ▼
3. Naming ─────────► Brand territory, candidate names, personality traits, and traits to avoid
      │
      ▼
4. Tagline & Pitch ─► One-line pitch and distinct tagline options
      │
      ▼
5. Visual Brief ───► Design direction: color mood, HEX palette, typography roles, shape/symbol language
      │
      ▼
6. Voice & Tone ───► Voice characteristics, Do/Don't communication rules, sample messaging
      │
      ▼
7. Launch Prep ────► Landing page headline and social launch post
      │
      ▼
[ Holistic Consistency Audit ] (Cross-system check for contradictions and alignment)
      │
      ▼
[ Kit Assembly & Markdown Export ] (Authoritative 10-section brand system export)
```

## 4. Architecture & Persistence Model

As documented in [`docs/architecture.md`](docs/architecture.md):

- **Stateless Backend**: The Node.js Express server is completely stateless and handles AI orchestration, structured prompt chaining, schema validation, and export assembly.
- **Client-Authoritative State**: The active browser session owns the canonical `SharedContext` in memory via Zustand.
- **Session Refresh Recovery**: `SharedContext` is mirrored to `sessionStorage` solely to protect user work against accidental page refreshes in the same tab. Closing the tab cleanly ends the session.
- **Zero Secrets on Client**: All LLM API keys (`OPENAI_API_KEY`, `GEMINI_API_KEY`) reside exclusively in backend environment configuration and are never exposed to browser bundles.

## 6. Local Development Setup

### Prerequisites
- **Node.js**: `>= 20.0.0`
- **npm**: `>= 10.0.0`

### Step 1: Clone Repository
```bash
git clone https://github.com/RaviprasadKumbhar/IdeaToBrand-AI.git
cd IdeaToBrand-AI
```

### Step 2: Configure Environment Variables
Copy `.env.example` to `.env`:
```bash
# On Linux / macOS
cp .env.example .env

# On Windows PowerShell
copy .env.example .env
```

Edit `.env` to configure your settings:
```env
# Application
NODE_ENV=development
PORT=5000

# AI Provider Credentials (Required for live generation)
AI_PROVIDER=OPENAI
OPENAI_API_KEY=your_actual_key_here
GEMINI_API_KEY=

# Backend & Client URLs
AI_REQUEST_TIMEOUT_MS=30000
VITE_API_BASE_URL=http://localhost:5000
```
> **Security Notice**: Never commit `.env` to Git. The repository's `.gitignore` prevents `.env` from ever entering version control.

### Step 3: Install Dependencies
```bash
npm install
```

### Step 4: Run Tests
Run the complete automated test suite (364 tests across root, backend, shared, and frontend):
```bash
# Root & backend unit, contract, API, security, and E2E QA tests
npm test

# Frontend UI, stage screens, and component tests
npm --prefix frontend test
```

### Step 5: Start Development Servers
Start both backend and frontend concurrently:
```bash
# Terminal 1: Backend API server (Runs on http://localhost:5000)
npm --prefix backend run dev

# Terminal 2: Frontend client (Runs on http://localhost:5173)
npm --prefix frontend run dev
```
Open **`http://localhost:5173`** in your browser.

## 9. Known Limitations (Transparent MVP Disclosure)

1. **Session Scope**: The MVP uses client-side `sessionStorage` for refresh recovery within an active browser tab. Multi-device cloud synchronization and user account management are planned for post-hackathon releases.
2. **Trademark Searches**: FOIL includes strict algorithmic guards against generating unsupported trademark claims (e.g. *"domain is available"* or *"unregistered trademark"*). Formal trademark verification requires real-time integration with USPTO/WIPO databases.
3. **Single Active Tab**: Each browser tab represents an isolated brand project workspace. Running concurrent tabs operates in separate project contexts.
